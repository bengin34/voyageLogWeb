# Technical, international SEO, structured data and site architecture findings

_Run: 2026-10-24. Scope: local build in `dist/` (144 HTML pages, 14 locales, 111 articles) plus read-only checks of the live site with `curl` and `gh api`. No analytics or Search Console data was available. No traffic, ranking or volume figures appear here._

Skills applied: `.agents/skills/seo-audit` (with `references/international-seo.md` and `references/title-tags.md`), `.agents/skills/schema`, `.agents/skills/site-architecture`.

Scratch scripts used for the checks (not part of the repo): a crawler that parses every `dist/**/*.html` file for title, description, canonical, hreflang, H1, JSON-LD and `<a href>`, followed by node one-liners for reciprocity, sitemap and link-graph checks. Each row below gives a command you can run again yourself.

## 1. Summary

- **The local build and the live site are different sites.** The live site has 35 URLs, all EN/DE/TR (`curl -s https://getvoyagelog.app/sitemap.xml | grep -c '<loc>'` gives `35`, and `https://getvoyagelog.app/ja/` returns `404`). The 11 new locales (`src/locales/`, `content/blog/{ar,es,fr,it,ja,ko,nl,pl,pt,ru,zh}/`, `src/lang.js`) are untracked in git. Anything that is cheap to change before launch, such as URL slugs, is cheapest now.
- **The international setup in the build is clean.** All 144 pages self-canonicalise (the one exception, `/en/`, does so on purpose). Every hreflang target exists, is canonical, has the right `html lang` and links back. There are no duplicate codes, and the sitemap and HTML annotations agree on every URL (0 mismatches). There is one small x-default inconsistency.
- **The biggest verified gaps are in hosting and architecture, not tags:**
  - HTTPS is not enforced on GitHub Pages.
  - There is no custom 404 page.
  - The home page body is rendered only by JavaScript: the static HTML holds 245 visible characters, made up of language links.
  - All 11 English articles link to the duplicate URL `/en/` instead of the canonical `/`.
  - The home page links to no article.
  - The "related posts" block shows the same 4 newest posts on every article, so 41 of 111 articles never appear in it.
- **Structured data:**
  - All JSON-LD parses. The types fit the pages (SoftwareApplication + FAQPage on home pages; BlogPosting + BreadcrumbList + FAQPage on articles; Blog on blog index pages).
  - FAQPage no longer earns a Google rich result. Per `.agents/skills/schema/SKILL.md`, FAQ rich results stopped in May 2026. Do not expect a SERP change from it.
  - The home pages have no `WebSite` or `Organization` node. `WebSite` is still the supported way to declare a site name.

## 3. Checked and found fine

- **Canonicals:** all 140 locale and blog pages self-canonicalise with absolute https URLs. `/en/` canonicalises to `/` by design (`src/locales/en.js:8` `path: '/'`).
- **Hreflang reciprocity:** 0 issues across 140 annotated pages. I checked for missing self-references, missing targets, non-canonical targets, `lang` mismatches, missing return links and duplicate codes.
- **Hreflang codes:** valid ISO 639-1 codes (`en de tr es fr it pt nl pl ru ja ko ar zh` plus `x-default`). No region codes, so there are no invalid region codes to fix.
- **x-default:** home pages point to `/` and blog indexes to `/en/blog/`. Translated articles point to the EN sibling (except #8).
- **Blog translations:** linked through frontmatter `key`. Clusters are 5×14, 2×13, 2×4, 2×3 and 1×1 languages, and every sibling links to every other.
- **Sitemap:** valid XML (`xmllint --noout dist/sitemap.xml`) with 143 unique URLs. Every URL exists on disk and is self-canonical. The only file not listed is `/en/`, which is correct. Annotations match the HTML on every URL. The file is 209 KB, far under the limits.
- **Sitemap lastmod:** comes from git commit dates or frontmatter `updated`, not the build time (`scripts/postbuild.mjs:17-28`). The values are 2026-10-24 ×125, 2026-10-23 ×14 and 2026-07-03 ×4.
- **robots.txt:** `Allow: /` plus the sitemap reference. Nothing is blocked, and there are no `noindex` meta tags anywhere.
- **Root redirect (`src/lang.js:24-30`):** runs only on `/`, uses `location.replace`, and never redirects English or unmatched browsers. Locale URLs are never redirected. Googlebot crawls without Accept-Language and with an English UI (hypothesis), so it should get `/` unredirected. There is no IP-based redirection.
- **Trailing slash and host:** `https://getvoyagelog.app/de` returns 301 to `/de/`. `https://www.getvoyagelog.app/` returns 301 to the apex.
- **H1:** exactly one H1 on every page, both static HTML and articles. On every article the title starts with the H1.
- **`<html lang>` and `dir`:** set per locale, with `dir="rtl"` on `/ar/`.
- **JSON-LD:** all blocks parse with `JSON.parse`, and none fail. BlogPosting carries headline, image, datePublished, dateModified, author, publisher and inLanguage.
- **OG images:** all 111 articles have their own OG image (0 fall back to `/assets/og.png`).
- **RSS:** all 14 `feed.xml` files are valid XML.
- **Duplicate metadata:** the only duplicate titles and descriptions are between `/` and `/en/`, which is expected and handled by the canonical.
- **Internal links:** 0 broken internal links across all 144 pages.
- **Images:** app screens use WebP with `srcset`, `width`/`height` (no CLS) and `loading="lazy"`, with the first screen eager (`src/App.jsx:122-139`). The font is self-hosted woff2 with `font-display: swap`.
- **Article pages:** load no JS bundle (CSS only). They are fully static, about 33 KB of HTML for the largest EN article.
- **Deploy:** `.github/workflows/deploy.yml` builds `dist` on push to `master`. OG PNGs are committed, not generated in CI, as `docs/seo-plan.md` says.
